    为什么描边不只是好看

    每个色块都被 2px 墨描边包住，所以色块自己不必承担边界对比度—— 浅绿、浅黄这类在奶油底上只有 2:1 的糖果色，也能安全地当填充用。 代价是：这些浅色永远不能拿来写字，写字只用墨色、深紫、深绿、深红四种。

    上面的对比度是浅色皮实测值（WCAG AA 要求正文 4.5:1）。 深色皮同样按这条规则挑色，落 token 时会再核一遍。

      手机端沿用同一套 token，只是尺寸降档：描边仍是 2px，硬投影收到 2px， 触控目标不低于 44×44。底部导航当前项＝葡萄紫实心胶囊， 和桌面端主导航是同一个语义（当前项＝主色实底）。

      迷你播放器做成一颗浮起的胶囊，压在底部导航之上——描边和硬投影让它 在任何封面之上都能被看清，不用再靠毛玻璃。

      五、不要清单 Never

      违者返工

      • 不要柔和阴影、毛玻璃、渐变按钮——层次只由「描边 + 硬投影」制造
      • 不要把糖果色当装饰随便撒；每一支只出现在它绑定的语义上
      • 不要用浅糖果色写字（浅绿/浅黄/浅粉只做底）
      • 不要中文标题用宋体——这张皮的标题是粗黑体，和纸·墨·朱正好相反
      • 不要 emoji 当图标，继续用 Phosphor 线性图标
      • 不要动信息架构、adapter、audio engine、stores、hooks——只换消费它们的样式层

      两张皮怎么并存

      这份原型的换皮机制就是打算落地的机制：
      1. <html> 上加 data-skin="pop|editorial"， 明暗仍走现有的 .dark。
      2. index.css 里颜色 token 之外，再抽一层 形状 / 字体 / 动效 token（描边宽度、圆角、投影、标题字族、缓动）。
      3. 组件只读 token。
      4. themeStore 加一个 skin 字段，持久化 + 启动脚本同步写入，避免闪烁。

      说明：原型里的「纸·墨·朱」是照 DESIGN v2 用同一套组件重画的近似版， 用来验证换皮机制，不是线上那份代码本身，细节会有出入。

      第 2 步是真正的工作量：现在组件里写死的 border、 rounded-md、font-serif 得换成 token 类，否则换皮只会换掉颜色、形状还留在编辑风。
