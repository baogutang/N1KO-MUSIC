## 0. 执行纪律（每个阶段都适用）

1. **分支**：全部工作在 `fix/audit-2026-10-10` 上（不存在就从 main 新建）。**不要 push，不要改版本号**（发版由 N1KO 决定）。
2. **门禁**（每阶段结束必须全绿，不绿不许提交）：
   ```bash
   cd frontend && npm run lint && npx tsc --noEmit && npm test && cd ..
   cd backend && npm test && cd ..
   npm run test:plugins && npm run check:versions
   ```
   依赖已安装（frontend/ 与 backend/ 的 node_modules 都在）。
3. **提交**：每阶段一个或几个 commit，中文 conventional 风格，与仓库历史一致，例如 `fix(audit): 阶段 1 —— 断网不再连跳、SourceShelves 三态`。
4. **每修一个 bug 加一条回归测试**（vitest / node:test），测试要走用户真正走的那条路径（历史教训：测了没人走的路，界面没变）。
5. **最小改动**：只修清单上的事，顺手重构仅限同一文件内明显重复。大文件拆分只在阶段 8 做，且以「行为不变、测试全绿」为前提。

7. **偏离记录**：凡与本文件或 `docs/sources/PROTOCOL.md` 不一致的取舍，追加到 `docs/sources/DECISIONS.md`，格式照旧（冲突/选择/原因/影响）。
8. **不要碰**：README 顶部的 N1KO-API 推广区块；任何 premium/会员概念（项目已全功能免费）；`.github/workflows` 的 tag 触发方式（阶段 5 只加 needs 与步骤）。
9. **插件改动必须升 manifest 的 patch 版本**（自动更新只比版本串），并更新 `plugins/catalog.json`。
10. 开始每个阶段前先 `git log --oneline -5` 看前一阶段做了什么，避免重复。

## 2. 阶段 2 · QQ 凭据生命周期 + 微信登录（issue #24）

- 实现刷新：CGI `music.login.LoginServer.Login`，param 按 loginType 分支（QQ=2：openid/access_token/refresh_token/expired_in/musicid/musickey/refresh_key/loginMode 2；微信=1：openid/refresh_token/str_musicid/musickey/unionid/refresh_key/loginMode 2），comm `tmeLoginType` = loginType。到期前主动刷新，刷新失败抛 `unauthorized`。

**2.2 微信扫码登录**（上游 luren-dc/QQMusicApi 已核对）：
- 取码：GET `https://open.weixin.qq.com/connect/qrconnect?appid=wx48db31d50e334801&redirect_uri=https://y.qq.com/portal/wx_redirect.html?login_type=2&surl=https://y.qq.com/&response_type=code&scope=snsapi_login&state=STATE&href=https://y.qq.com/mediastyle/music_v17/src/css/popup_wechat.css#wechat_redirect`，responseType text，正则 `uuid=(.+?)"` 取 uuid；再 GET `https://open.weixin.qq.com/connect/qrcode/{uuid}`（Referer `https://open.weixin.qq.com/connect/qrconnect`，arraybuffer）→ `data:image/jpeg;base64,...` 作为 qrImage。
