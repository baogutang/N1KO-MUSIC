# N1KO MUSIC 1.11.5 全局审阅与改进清单

审阅日期：2026-09-07。用途：供开发 Agent（Claude）复核、拆分修复并验收；本次未修改业务代码。

## 判断

项目已经有可用的 NAS 播放基础，网易云和 QQ 也都有实际可走通的播放路径。当前最需要补齐的是多音源之间的行为一致性：用户选中的歌不能被过期请求替换；操作必须落在正确账号与音源；推荐必须尊重屏蔽和已知播放权限；界面说“更新完成”“查看全部”时，后续行为必须符合这个承诺。

目前推荐的实现是“本地收听画像产生候选，加上平台每日推荐，再轮转合并”。本地部分已经包含历史衰减、跳过惩罚、新鲜度、探索以及歌手/专辑多样性约束，不能简单评价为纯随机。但平台候选没有统一经过同一套最终约束和排序，首页与推荐页也不是同一批数据的两个视图。当前证据支持先修数据和流程，不足以支持直接更换复杂推荐模型。

清单共 **18 项问题、5 项体验/产品建议**。其中 **F01–F05 建议优先修复**。本次未确认 P0 级问题；这不等于全平台安全或长期稳定性认证。

## 问题清单

### F01 · P1 · 旧歌曲的失败回调会抢走用户新选中的歌曲

**证据：B；位置：** `frontend/src/hooks/useAudioEngine.ts:675–753`。

触发：先播放 QQ 的 A，取流未结束；用户改播 NAS 的 B；A 随后返回 `forbidden`，换源找到 NAS 的 A。真实 Hook 的隔离探针证明，当前歌曲从 B 被替换成 A 的替代版本。

成功取流分支有加载序号检查，但 `catch` 进入失败处理前、以及 `await tryFallbackSource` 返回后没有相同检查。过期请求还可能改变缓冲状态、弹提示或影响连续失败计数。自动跳过的身份判断也只比较歌曲 ID。

**建议：** 每次加载绑定请求代次与 `{serverId, songId, queueEntryId}`；所有异步返回、失败处理和延迟回调先确认仍属于当前播放意图。仅取消成功分支不够。连续失败停止时同步播放状态。

**验收：** A 慢成功、慢失败、换源查询未完成三个阶段分别切到 B，B 均不被替换；相同 ID、不同音源也成立；达到跳过上限后明确处于停止/失败状态。

### F02 · P1 · 指定音源已断开时，收藏请求仍回落到主 NAS

**证据：B；位置：** `frontend/src/hooks/useServerQueries.ts:679–709`。

`findAdapterFor(sourceId) ?? getAdapter()` 会把原音源的 ID 交给主库。探针将原音源移出适配器注册表后，确认 NAS 的 `star('foreign-id', 'song')` 被调用。若两边 ID 碰巧相同，存在修改错误对象的可能；本次未对真实收藏做写入验证。

**建议：** 已明确来源的写操作必须严格使用该来源，断开时返回可理解的错误并引导重连。同步检查播放条收藏成功回调：`PlayerBar.tsx:264–269` 无条件更新“此刻的歌曲”，应防止请求期间切歌后把新歌心形状态改掉。

**验收：** 断源、删除源、请求中切源时，其他音源收到的收藏/取消收藏请求为 0；慢收藏完成后不会改变后来切到的歌曲状态。

### F03 · P1 · QQ 雷达把非歌曲数据送进了推荐和播放队列

**证据：A+B；位置：** `plugins/qqmusic/index.js:135–171,468`；`frontend/src/api/adapters/plugin.ts:488–493`。

更新并刷新后，本机 QQ 推荐仅有一项 **Haley Smalls**，歌手/专辑空白，显示 **1 首 · 0:00**。点击后仍显示播放状态而进度停在 0:00。

解析器把任何包含 `mid/songmid` 的数组当作歌曲。合成的 `tracks[].track_info.singer[]` 响应经过真实插件后，输出的是歌手 ID、歌手名和 0 秒“歌曲”。每日推荐适配器又直接映射结果，未做有效歌曲形状检查。**本机异常的原始响应没有抓取，因此“恰好走入 singer[]”是与代码、夹具吻合的原因判断，不能冒充真实响应已证实。**

**建议：** 对已知歌曲包装字段明确解包；禁止递归把任意实体数组猜成歌曲。建立歌曲输入校验，缺失核心字段时记录结构错误并显示该来源暂不可用，不把异常条目入队。

**验收：** 真实账号脱敏雷达响应与歌手/专辑干扰夹具都通过；推荐条目身份正确；异常响应不产生假歌曲或持续“播放中”。

### F04 · P1 · 插件显示已更新，当前运行的插件仍可能是旧版

**证据：A+B+C；位置：** `frontend/src/plugins/host/pluginStore.ts:173–195,235–240,300`；`pluginRuntime.ts:61–96`；`SourcesSettings.tsx:83`；`Login.tsx:88`。

本机进入设置才出现自动更新提示。代码中插件 `load()` 由登录页/设置页调用，已有连接恢复的启动路径没有同样的更新初始化。更新提交更改存储和列表，但已运行宿主只按凭据判断是否复用。探针把已安装版本从 v1 改到 v2 后再次取得宿主，得到的仍是 v1。

**建议：** 将插件加载/更新检查纳入应用生命周期；让运行宿主包含版本或代码摘要身份。更新后按安全时机重建宿主并清理相关查询/原始曲目缓存；若需要刷新才能生效，明确显示“已安装，待重载”。

**验收：** 已登录用户覆盖安装新应用后，无须先去设置；界面显示的已生效版本与宿主执行版本一致；保留登录凭据；旧请求不能污染新宿主状态。

### F05 · P1 · 推荐的屏蔽和播放权限过滤存在绕路

**证据：B+C；位置：** `usePersonalizedRecommendations.ts:188–235`；`useSourceQueries.ts:318–347`。

两项探针确认：①生成推荐后屏蔽该歌手，重新挂载且使用新查询缓存，仍从持久化推荐缓存拿到被屏蔽歌曲；②明确非 VIP 的网易云账号，其 VIP 收藏可从外源收藏候选进入本地推荐。另据代码，平台每日推荐没有经过本地 `readMutedSets()`，VIP 过滤只覆盖平台每日推荐入口。

**建议：** 在所有候选合并后、最终展示/生成队列前统一应用硬约束：屏蔽、有效来源、已知不可播放、异常条目。缓存读取也要过滤；屏蔽与账户能力变化及时使相应结果失效。未知权限不要随意推断为无权，能够切到有权替代源的歌曲也应正确保留。

**验收：** 首页、推荐页、缓存、历史、收藏、平台每日推荐六条入口一致；屏蔽立即生效；已知不可播放且无可用替代版本的歌不被主动推荐。

### F06 · P2 · 多源画像丢失种子来源，再用主库查询外源 ID

**证据：B+C；位置：** `usePersonalizedRecommendations.ts:46–79,168–207`；`recommendationEngine.ts:378–415`。

画像读取所有已连接来源的历史，但 `deriveRecommendationSeeds` 输出裸歌曲 ID；后续全部传给主库的 `getSimilarSongs`。探针证实 QQ 历史产生的 `qq-only-id` 不再带来源信息。这会造成无效查询，ID 碰撞时还可能请求错误对象。歌手种子也应检查采用 ID 的适配器。

**建议：** 种子保留来源，路由回所属适配器。跨源迁移需要明确的音乐实体匹配，不能直接复用平台 ID。

**验收：** QQ/网易云歌曲 ID 不出现在 NAS 相似曲查询中；相同 ID 的不同源事件互不混淆；不支持相似曲的来源安静降级。

### F07 · P2 · 首页“查看全部”不是当前推荐的展开版

**证据：A+C；位置：** `components/sources/SourceShelves.tsx:44–90`；`pages/Recommendations.tsx:34–91`。

本机首页 20 首以《爱错》开始；进入推荐页，加载完成后为 60 首，首曲变为《你不知道的事》。代码分别以 20/60 生成不同候选与持久化缓存，而且首页按产出池合并、推荐页重新按歌曲来源分组，排序也会不同。

**建议：** 生成一个带日期、批次和完整顺序的推荐快照。首页截取前 20，详情展开同一快照，播放全部使用同一序列。

**验收：** 所有来源加载完成后，从首页展开前 20 首及顺序一致；返回首页、刷新、切换来源筛选后批次可解释；“换一批”同步影响两个页面。

### F08 · P2 · 推荐去重会把录音室版与 Live/重制版直接合并

**证据：B；位置：** `frontend/src/hooks/useSourceQueries.ts:280–308`。

去重删除全部括号内容，仅保留歌名和歌手。探针输入同歌手 180 秒原版与 320 秒 Live，后者被直接丢弃。其判断还与搜索中的同曲匹配规则分离。

**建议：** 区分作品与录音版本；保留 Live、翻唱、Remix、伴奏等版本标记，辅助比较歌手、专辑和时长。确定是同一录音时才聚合多个播放来源，而不是丢掉替代源信息。

**验收：** 不同录音保留；同一录音跨源可切换；缺字段时宁可保留待确认项，不误删明显不同版本。

### F09 · P2 · 榜单浏览链路不完整：入口跳错、详情丢分页

**证据：A+B+C；位置：** `SourceShelves.tsx:156–194`；`useSourceQueries.ts:351–359`；`pages/TopListDetail.tsx`。

首页截断榜单后，“查看全部”跳到只有每日歌曲的 `/recommendations`，没有完整榜单目录。详情 Hook 又固定读取第 0 页并只返回 `songs`，丢弃 `isEnd`。探针返回 `isEnd:false` 后，确认没有读取下一页。

**建议：** 提供真实的全部榜单目录；详情保留分页信息，支持加载更多。区分播放已加载曲目与播放完整榜单，避免“全部”仅包含第一页。

**验收：** 首页被折叠的榜单都能找到；超过一页的榜单可以到达末尾，顺序不重不漏；播放范围与按钮文案一致。

### F10 · P2 · 不支持收藏的音源，仍有可点击收藏入口

**证据：A+C；位置：** `components/layout/PlayerBar.tsx:331–343`；`components/player/FullscreenPlayer.tsx:583,725`；`SourceShelves.tsx:130–136`；`api/adapters/plugin.ts:328–335`。

QQ manifest 没有 favorites 能力；歌曲列表会隐藏对应心形，但播放条、全屏播放器仍展示，首页 QQ 卡片也有“收藏”。适配器最终抛出不支持收藏。于是同一首歌在不同页面有不同能力。

**建议：** 统一按来源能力控制全部入口；若要提供“本地喜欢”，明确产品语义、存储位置和同步范围，再单独实现。

**验收：** 同一音源在列表/播放条/全屏/首页表现一致；不存在点击后才告诉用户该功能根本不支持的常驻操作。

### F11 · P2 · 歌词解析规则不一致，原始元数据会直接展示

**证据：A+B；位置：** `api/adapters/plugin.ts:185–191`；`api/adapters/subsonic.ts:1102`；`hooks/useLyrics.ts:39–71`。

本机网易云 Straight A's 歌词可见 JSON 格式的作词/作曲元数据。隔离检查还发现整秒标签 `[00:12]`：适配器解析为 0 秒普通文本；另一解析器得到 12 秒，但没去掉显示中的时间标签。插件提供的 translation 字段也未被这个适配器输出。

**建议：** 收敛为统一标准化解析流程，识别平台元数据、整秒/小数时间、偏移和翻译；展示层只接收规范歌词对象。

**验收：** JSON 不以歌词正文出现；两种时间标签同步一致且不露原始标签；原文/译文按产品开关正确展示。

### F12 · P2 · 部分推荐/榜单失败被隐藏，现有日志难定位业务错误

**证据：A+C；位置：** `SourceShelves.tsx:47,159` 及推荐歌单区；`Recommendations.tsx:60–71`；`plugins/host/PluginHost.ts:414–422`。

每日推荐和榜单筛掉无数据/失败分组，用户不能区分“这个源没有推荐”与“请求或解析失败”。设置中的 QQ 日志主要是同一路径 `musicu.fcg` 的 HTTP 200 和耗时，无法区分 RPC 方法及业务错误。首页“我的音乐库”已有 `SourceGroupState`，可复用相同体验。

**建议：** 每个来源明确加载、空内容、登录失效、暂时失败，并允许定向重试。增加脱敏的插件方法名、业务错误码、解析阶段和关联 ID；保留现有不记录 Cookie/正文的原则。

**验收：** 模拟单源 HTTP 200 但业务失败，其他来源仍正常，失败来源有原因和重试；诊断能区分登录、权限、解析和网络错误且不暴露凭据。

### F13 · P2 · 搜索歌曲要等待额外类型请求，换源搜索也受影响

**证据：C；位置：** `frontend/src/api/adapters/plugin.ts:158–177`；`pages/Search.tsx`；`hooks/useAudioEngine.ts:161–175`。

插件 `searchAll` 先等歌曲搜索，再等专辑、歌手、歌单三个请求，最后才返回已有歌曲。搜索页没有展示这里取回的歌单结果。自动换源调用同一个入口，也可能等待与当前播放目标无关的请求。当前方法没有接收查询取消信号。

**建议：** 歌曲结果先返回/展示；专辑、歌手、歌单按选中类型或独立渐进加载。自动换源使用有时间预算的歌曲检索；过期关键词结果取消或可靠忽略。

**验收：** 模拟歌单/专辑请求卡住，歌曲仍立即可显示和用于换源；连续输入不会让旧结果覆盖新结果；明确记录每个关键词的请求数与首批歌曲耗时。

### F14 · P2 · QQ 无损取流失败直接判整曲不可播放，缺少音质层面的降级

**证据：B+C；位置：** `plugins/qqmusic/index.js:879–905`。

本机 Wi-Fi/移动音质都设置为无损。插件为所选音质只请求一次文件；夹具返回 104003 后，仅发生一次 `F000…flac` 请求，没有尝试较低音质，随后进入整曲拒绝/换源逻辑。

**边界：** 这证明没有音质降级，不证明真实账号对该歌曲的低音质一定有权限。更新后的 QQ 样本已有成功播放，不能据此说无损设置导致所有 QQ 歌曲失败。

**建议：** 区分音质不可用、整曲无权和账号/设备限制；仅在允许降级的设置与适当错误类型下尝试可用音质，并显示实际播放品质。整曲无权时尊重权限。

**验收：** 高音质不可用但标准音质可用时可继续播放；全部无权时有准确说明，重试次数有上限；不把设备受限一律描述成 VIP。

### F15 · P2 · 多源统计和“我的口味”采用了不同的数据口径

**证据：C；位置：** `services/listeningStats.ts:97–112`；`components/music/TasteProfile.tsx:49–55`；`usePersonalizedRecommendations.ts:156–173`。

统计的歌曲键带来源，但专辑键仅为 `albumId ?? album`，不同来源同 ID、不同专辑可能被并在一起。“我的口味”只读主库历史，且只随主库 ID 变动重新计算；推荐画像却读所有已连接来源。历史事件监听还只为主库事件刷新画像。

**建议：** 所有按源实体的统计键统一带来源；跨源作品聚合另外设计。口味面板和推荐引擎共享历史范围与更新订阅，并把“当前范围”告知用户。

**验收：** 两源同专辑 ID、不同名称分别统计；新增 QQ/网易云有效收听后，面板与引擎按同一规则更新；断开来源后的历史口径明确。

### F16 · P2 · 同步后端 first-user 注册模式存在并发窗口

**证据：B，真实后端+临时数据库；位置：** `backend/src/routes/auth.ts:36–64`。

空库采用 `first-user` 时，两个不同用户名并发注册，实测 **[201,201]，用户数 2**。允许注册检查发生在异步密码哈希之前，写入时没有再次原子检查。顺序注册测试通过不覆盖这个场景。

**边界：** 仅影响启用该同步后端、且数据库还没有首个用户的初始化窗口；不表示已有账号的 NAS 音乐被读取，也未对线上服务试验。

**建议：** 在写入事务/原子条件中重新检查首次注册资格，支持多进程而不只加进程内布尔锁。

**验收：** 并发不同用户名只有一个成功且库内只有一个用户；`open` 模式仍允许多个；`closed` 始终拒绝；覆盖多实例访问同一数据库的部署方式。

### F17 · P2 · 全屏播放器的辅助操作语义不完整

**证据：A+C；位置：** `components/player/FullscreenPlayerOverlay.tsx:51–63`；`FullscreenPlayer.tsx` 桌面控制区；`components/sources/SourceBadge.tsx:94–112`。

本机可访问性树中，全屏的关闭、更多、收藏/加入歌单等部分按钮没有名称；底层搜索结果与导航仍完整暴露。浮层只有固定定位，没有模态语义与焦点管理。紧凑来源图标是空 alt 或 aria-hidden，辅助工具不能读出当前来源。未完成 VoiceOver 全流程及键盘陷阱的独立实测，不宣称已测得所有键盘问题。

**建议：** 完整命名图标按钮；补全屏焦点进入、限制、关闭恢复，底层正确隔离；歌曲的来源作为可读取信息提供。

**验收：** 键盘和 VoiceOver 能完成打开、暂停、收藏/可用操作、关闭；全屏时焦点不进入背后的搜索结果；能够读出音源，关闭后回到触发位置。

### F18 · P2 · 发布检查缺少这次最容易出问题的插件与整条播放路径

**证据：C + 本次检查结果；位置：** `.github/workflows/ci.yml`；根目录 `test:plugins`；`frontend/src/hooks/useAudioEngine.ts`。

当前主 CI 跑前后端测试、lint、构建和 Cargo 检查，没有调用根目录插件测试，也没有已安装桌面环境的三音源冒烟。现有 761 项前端测试通过，但本次真实 Hook 边界探针仍能稳定复现抢歌、错源收藏、屏蔽失效。

**建议：** 把纯夹具插件测试纳入常规 CI；将 F01–F05 的正确行为作为回归门禁；发布前单独记录真实桌面三音源样本结果。联网账号测试应受控运行，不能把跳过算通过。播放引擎的拆分可围绕这些状态边界逐步进行。

**验收：** 发布记录明确标注单元/插件夹具/真实账号/安装包四层结果；覆盖冷启动、插件升级、搜索、取流、快速切歌、断源、偏好过滤。新增失败用例能先红后绿，而非只测试重复实现逻辑的辅助函数。
