## 0. 执行纪律（每个阶段都适用）

1. **分支**：全部工作在 `fix/audit-2026-10-12` 上（从 main 新建）。**不要 push，不要改任何版本号**（app 七处版本号由 N1KO 发版时改）。
2. **门禁**（每阶段结束必须全绿，不绿不许提交）：
   ```bash
   cd frontend && npm run lint && npx tsc --noEmit && npm test && npm run build && cd ..
   cd backend && npm test && cd ..
   npm run test:plugins && npm run lint:plugins && npm run check:versions
   npm run audit:check -- frontend && npm run audit:check -- backend
   ```
   依赖已安装。本机**没有 Rust 工具链**，`cargo check --locked` 交给 CI；因此**不要动 `frontend/src-tauri/Cargo.*`**。
3. **提交**：每阶段一个或几个 commit，中文 conventional 风格，例如 `fix(audit-2): 阶段 1 —— 网易歌单写入可达、插件登录死局、详情页带源`。**只 `git add` 明确的文件，禁止 `git add -A`**：工作区里 `website/` 三个文件有另一方正在进行的未提交改动，不许碰、不许提交、不许 stash。
4. **每修一个 bug 加一条回归测试**（vitest / node:test），测试要走用户真正走的那条路径（历史教训：测了没人走的路，界面没变；harness 语义要与真沙箱一致——`plugins/test/harness.mjs` 的 setCredentials 是快照语义，别改回去）。**用 fs 读仓库文件的测试不许写死 `\n`**（Windows runner autocrlf 后是 CRLF，v1.11.7 第一次打标签就因此只缺 Windows 产物），用 `\s*` / `\r?\n`。
5. **最小改动**：只修清单上的事。大文件拆分只在阶段 5 做，且以「行为不变、测试全绿」为前提。
6. **设计纲领**（改 UI 必读）：真源是 `frontend/src/index.css` 的 token 块与 `tailwind.config.ts`；`docs/redesign/DESIGN.md` 已过期不要照着做。三张皮 clay（默认）/pop/editorial 共用组件，差异靠 `pop:`/`editorial:` 变体（`pop:` 同时匹配 pop 与 clay），组件里不要读 store 拼 className。图标只用 `@phosphor-icons/react` 的 regular/fill/bold 三种字重。数字加 `font-num`。长 CJK 标题 `truncate + min-w-0`。`.latin-tag` 与 `.section-head h2 small` 在 clay 与英文界面下 display:none，状态/类型标记绝不能放进去。全局单一强调色，红只给 destructive。「一个字不编」：界面上任何自动生成的句子必须由真实数据撑起。Dialog 必须有 Title（可视觉隐藏）。根节点 `onKeyDown` 开头必须 `if (e.target !== e.currentTarget) return`。
7. **偏离记录**：凡与本文件或 `docs/sources/PROTOCOL.md` 不一致的取舍，追加到 `docs/sources/DECISIONS.md`，格式照旧（冲突/选择/原因/影响）。每阶段结束在 `docs/sources/PROGRESS.md` 追加一节「2026-10-12 第四轮 · 阶段 N」。
8. **不要碰**：`website/`（另一方在改）；`README.md` / `README_CN.md` 顶部的 N1KO-API 推广区块；`.github/workflows` 的 tag 触发方式；`frontend/src-tauri/Cargo.*`；dependabot 的 PR（由 N1KO 处理）。README 其余部分可以改（阶段 6 有两处要改）。
9. **插件改动必须升 manifest 的 patch 版本**并同步 `plugins/catalog.json`（当前 netease 0.1.13、qqmusic 0.1.16、mock 看文件）。宿主侧 `scripts/check-plugin-versions.mjs` 会在 CI 比对。
10. 开始每个阶段前先 `git log --oneline -5` 看前一阶段做了什么，避免重复。
